# 유압 휴머노이드 v9 — 물리 시뮬레이션 + 보행 강화학습

설계한 v9 모델(CAD)을 그대로 MuJoCo로 옮기고, 그 위에 유압 시스템 전체를 물리 모델로 붙였습니다. 신경망은 이 시뮬레이터 안에서 보행을 학습합니다.

## 무엇이 시뮬레이션되나

| 계층 | 내용 |
|---|---|
| **강체** | 31개 바디, 35 자유도(몸통 6 + 구동 관절 29: 허리 3, 다리 6×2, 팔 7×2). 질량·관성은 CAD 부품 부피 × 재질 밀도로 계산, EMRAX 모터·어큐뮬레이터는 실제 무게로 지정(총 99.6 kg). v10: 다리 +20 cm(허벅지·정강이 각 +10 cm, `legs.py`) |
| **기구학** | 무릎 4절 링크, 발목 십자 U조인트 + 아킬레스 실린더 2개, 허리 U조인트 + 등 실린더 2개, 팔꿈치 삼두 실린더(올레크라논 혼). 실린더 길이와 모멘트 암을 CAD 치수로 정확히 계산해서 힘 → 관절 토크로 변환(`kinematics.py`) |
| **서보밸브** | 스풀 1차 지연(3 ms), 임계중심 4-way 오리피스 유량 Q = K·x·√Δp, 중립 누설 |
| **실린더 / 베인** | 챔버 2개마다 오일 압축성(β = 7000 bar), 호스 데드볼륨, 스트로크에 따른 체적 변화, 피스톤 간 누설, 실 마찰, 스트로크 끝 스토퍼 |
| **오일 관성** | 호스 안 오일 기둥의 관성을 관절 armature로 반영 |
| **A-B 바이패스** | 비례 바이패스 밸브. 전원이 꺼지면 자동으로 열려 다리가 흐느적거리는(limp) 상태가 됨 |
| **공급계** | EMRAX 188 LV 수랭(88 V에서 최고 4900 rpm, 회전자 관성 0.0152 kg·m², 전기 입력 15 kW 제한) + 10 cc/rev 내접기어펌프(체적효율 포함), 압력 피드백 속도 제어, 1 L 피스톤 어큐뮬레이터 2개 = 2 L(폴리트로픽 가스, 140 bar 프리차지), 230 bar 릴리프 |
| **열·전기** | 스로틀링·펌프 손실 → 오일 온도(쿨러 UA), 온도에 따른 누설 변화, 배터리 전력·전류·에너지 |
| **센서** | IMU, 엔코더, 챔버 압력센서(→ 힘·토크 추정), 공급 압력, 발 6축 F/T. 학습 시 노이즈 포함 |
| **펌웨어(1 kHz)** | 관절 임피던스 → J⁻ᵀ로 실린더 힘 목표 → 압력 피드백 + 속도 보상으로 서보밸브 지령. 실제 로봇에 들어갈 제어 구조와 같음 |

물리 스텝은 1 ms입니다. 강체와 유압은 symplectic 방식으로 결합합니다(압력으로 힘을 계산하고, 강체를 한 스텝 진행한 뒤, 새 속도로 압력을 적분). 오일 기둥처럼 딱딱한 계가 1 ms에서도 안정적으로 돌기 때문에 이렇게 했습니다.

신경망 정책은 50 Hz로 관절 목표각을 내고, 그 아래는 전부 위의 유압 물리를 거칩니다. 정책이 보는 관측은 실제 로봇에 있는 센서뿐입니다. critic(가치망)만 학습용으로 실제 속도, 접촉, 유압 내부 상태를 추가로 봅니다.

## 설치 (Linux Mint, NVIDIA GPU)

```bash
./setup.sh                    # .venv 생성 + jax[cuda12] 등 설치. NVIDIA 드라이버 535 이상 권장
source .venv/bin/activate
```

## 실행

```bash
python viewer.py                          # 학습 전: 서 있기 데모, 슬라이더로 관절 조작
python bench.py 1024                      # 내 GPU에서 두 학습 단계의 속도와 예상 시간
python train_walk.py                      # 보행 학습 (1단계 → 2단계 자동 진행, 대시보드 표시)
python watch.py runs/walk                 # (다른 터미널) 학습 중인 로봇을 3D로 실시간 관찰
python viewer.py runs/walk/policy.pkl     # 학습된 정책으로 걷기 (3번 키)
python rollout_video.py runs/walk/policy.pkl walk.mp4 8 0.6   # 화면 없이 영상 + 텔레메트리 CSV
```

## 학습 (`train_walk.py`)

학습은 두 단계로 나눠서 진행합니다. GTX 1060 같은 GPU에서도 돌릴 수 있게 하려는 구성입니다.

| 단계 | 물리 | 기본 스텝 | 하는 일 |
|---|---|---|---|
| 1 `fast` | 축약 액추에이터 모델, 4 ms | 1.5억 | 걷는 법의 대부분을 익힘 |
| 2 `full` | 완전한 유압 모델, 1 ms | 2천만 | 밸브 지연, 오일 압축성, 공급 압력 처짐에 적응 |

축약 모델(`hydraulics.fast_step`)은 완전 모델과 같은 파라미터에서 계산합니다. 들어간 것은 다음과 같습니다.
- 공급 압력 × 면적으로 정해지는 힘 한계(정확한 기구학으로 관절에 전달)
- 밸브 유량 한계 때문에 빨리 움직일수록 줄어드는 힘
- 약 6 ms의 힘 응답 지연
- 펌프와 어큐뮬레이터 공급, 압력 처짐

**터미널 대시보드**에는 이런 값들이 계속 갱신됩니다.
- 단계, 진행률 막대(단계별·전체), 초당 스텝, 남은 시간(단계 / 전체)
- 끝난 에피소드 수, 평균 리턴, 평균 에피소드 길이(초), 넘어진 비율, 속도 추종 점수
- 평균 유압 전력과 공급 압력, 정책 표준편차, 손실값, 마지막 체크포인트 시각

처음 실행할 때는 GPU용 코드를 컴파일하느라 몇 분 걸리고, 그동안 경과 시간이 표시됩니다. 컴파일 결과는 `runs/.jax_cache`에 저장되어 두 번째부터는 훨씬 빨리 시작합니다.

**중단과 재개:** `Ctrl+C`를 한 번 누르면 체크포인트를 저장하고 끝납니다. 같은 명령을 다시 실행하면 저장한 그 시점(옵티마이저 상태 포함)부터 이어서 학습합니다. 체크포인트는 5분마다(`--ckpt-min`) 자동으로도 저장됩니다.
Ctrl+C를 두 번 누르면 저장하지 않고 즉시 종료합니다.

**실시간 관찰:** 학습기는 2 iteration마다 로봇 4대의 최근 동작을 `live.npz`로 내보냅니다(성능 영향은 거의 없음). `watch.py`가 이걸 MuJoCo 창에서 재생합니다.
- `1`~`4` 키: 볼 로봇 선택
- `F`: 카메라 따라가기 켜고 끄기
- `Space`: 일시정지
- 학습 중인 실제 시도라서 탐색 노이즈가 섞인 움직임 그대로 보입니다.

**자주 쓰는 옵션**
- `--envs 512`: GPU 메모리가 부족할 때
- `--fast-steps 3e8`: 1단계를 더 길게
- `--run runs/try2`: 다른 실험 폴더

**결과 파일:** `ckpt.pkl`(재개용), `policy.pkl`(뷰어용), `log.csv`(학습 기록)

**뷰어 모드**
- `1` STAND: 데모 균형 제어로 서 있음 (시작 모드)
- `2` MANUAL: 오른쪽 **Control 패널의 슬라이더 29개**로 관절을 직접 움직임(단위: 도). 슬라이더 값은 관절에 그 각도를 강제로 넣는 게 아니라 펌웨어에 주는 **목표값**입니다. 펌웨어가 서보밸브를 열고, 오일 압력이 힘을 만들어서 움직입니다. 그래서 부하가 크거나 펌프 유량이 모자라면 실제 관절이 늦게 따라오고, 화면 위쪽에 최대 추종 오차가 표시됩니다. 다리를 움직일 때는 `H`(갠트리)로 골반을 공중에 잡아두면 편합니다.
- `3` POLICY: 학습된 정책 (파라미터 파일을 줬을 때). 화살표 ↑↓ 속도, ←→ 회전, `,` `.` 옆걸음, Space 정지.

**키:** `G` 전체 슬로모션 1× → 1/4 → 1/10 → 1/40 → 1/100, `H` 갠트리(골반 고정) 켜기/끄기, `P` 몸통 밀기, `M` 유압 ON/OFF(끄면 바이패스가 열려 다리가 풀림), `R` 리셋.
MuJoCo 뷰어 패널은 Tab / Shift+Tab으로 열고 닫습니다. 슬라이더는 오른쪽 패널의 Control 항목에 있습니다.

**펌프:** 가슴 유리 케이스 안의 피니언(17T)과 편심 링기어(23T)가 시뮬레이션 속 BLDC 회전수 그대로 돕니다. 링기어는 17/23 비율로 돕니다.
수천 rpm이라 실시간(1×)으로는 이가 잘 안 보이고, `G`로 1/40 정도로 늦추면 이 하나하나가 맞물려 도는 게 보입니다. 이때는 시뮬레이션 전체가 같이 느려집니다.
`python demo_pump.py pump.mp4`를 실행하면 팔을 급하게 드는 순간 펌프가 700 rpm에서 수천 rpm까지 올라가는 장면을 1/33 슬로모션 영상으로 만들어 줍니다.

학습 중에는 `runs/walk/params.pkl`이 평가할 때마다 덮어써집니다. 중간에 뷰어로 열어봐도 되고, 끊겼으면 `--resume runs/walk/params.pkl`로 이어서 할 수 있습니다.
진행 기록은 `runs/walk/log.json`에 쌓입니다.

## 확인된 것 (이 CPU 환경에서)

- 정지 상태로 놔둔 유압 스프링: 발산 없이 감쇠함 (`test_hung.py`, 1 ms)
- 공중에 매단 상태의 추종: 무릎 24°→100°를 약 0.15 s, 고관절 12°→70°를 약 0.2 s에 도달
- 서 있기 + 180 N 밀기: 버팀. 대기 유압 전력 약 450 W, 공급 압력 207 bar 유지
- 학습 파이프라인(PPO, 비대칭 관측, 도메인 랜덤화): 두 단계 모두 짧게 끝까지 돌려 봄. 중간에 끊었다가 이어가기도 확인
- **본 학습은 GPU가 없어서 여기서 끝까지 돌려보지 못했습니다.** 보상 가중치는 첫 실행 결과를 보고 조정해야 할 수 있습니다(`walk_env.py`의 `reward =` 한 줄).

## 단순화한 것 (알고 쓰세요)

- 링크 부품(로커, 커플러, 실린더 바디)은 MuJoCo 바디가 아닙니다. 질량은 부모 바디에 합쳤고, 힘은 정확한 기구학으로 전달합니다. 뷰어에서는 매 프레임 위치를 계산해서 그립니다. 이 부품들끼리의 간섭은 CAD 단계(0~140°, 8개 자세)에서 이미 검사했습니다.
- 팔은 7축 모두 움직입니다: 어깨 피치·롤·요(베인), 팔꿈치(삼두 실린더), 전완 롤, 손목 피치·요(베인). 팔은 몸통, 골반, 다리와 충돌합니다. 학습 중에는 팔을 균형 잡는 데 써도 되지만, 기본 자세에서 너무 벗어나면 약하게 감점합니다.
- 목은 고정했습니다. 손은 제거했고, 팔 끝은 손목 6축 F/T 센서와 툴 플랜지입니다(CAD도 같이 수정: 손, 손가락, 손가락 밸브팩과 그 배관 삭제).
- 팔꿈치는 지금 CAD 구조(혼을 미는 직결식)대로라서 0~110°까지만 쓸 수 있습니다. 128° 근처에서 특이점이 생기는데, 무릎처럼 4절 링크로 바꾸면 더 굽힐 수 있습니다.
- 프레임 탄성(BeamNG식 변형)은 계산하지 않습니다.
- 유압 수치(베인 배제용량, 밸브 정격유량, 데드볼륨 등)는 설계 추정값입니다. 실제 부품을 고르면 `hydraulics.py`의 `default_params()`만 바꾸면 됩니다.
- 발 크기는 96 × 213 mm라서 균형 잡기가 빠듯한 편입니다.
